# plainrussian-ng

Новая версия [plainrussian.ru](https://plainrussian.ru): оценка простоты (читаемости)
русскоязычных текстов. Расчёт идёт на стороне пользователя (WebAssembly в браузере,
нативно в настольном приложении), поэтому текст никуда не отправляется.

## Состояние

Фаза 6: проверки ясного языка с морфологическим анализом — на сайте, в приложении,
командной строке, Python и MCP.

- `crates/pr-core` — ядро:
  - `readability` — текущий алгоритм: предложения по правилам razdel, слова с дефисами,
    слоги по гласным любого регистра, пять формул с новыми коэффициентами и их среднее
    как главная оценка; версия калибровки входит в каждый результат;
  - `sentenize` — перенос `razdel.sentenize` на Rust (лицензия MIT, см. `third_party/razdel`);
  - `clarity` (feature `clarity`) — проверки ясного языка на морфологии
    [rumorph](https://github.com/SergeyShk/ruMorph) (см. `third_party/rumorph`);
  - `legacy` — старый plainrussian.ru один в один: те же счётчики, формулы и формат ответа
    `/api/1.0/ru/measure/`, вместе с ошибками подсчёта.
- `crates/pr-cli` — команда `plainrussian`: оценка файлов, каталогов и стандартного ввода,
  вывод сводкой, JSON или CSV.
- `crates/pr-server` — `plainrussian-server`: HTTP API в формате старого
  `/api/1.0/ru/measure/` для прежних интеграций.
- `crates/pr-py` — Python-пакет `plainrussian` (PyO3) с MCP-сервером `plainrussian-mcp`;
  заменяет старые `textmetric` и `plainrussian-mcp`, spaCy больше не нужен.
- `crates/pr-wasm` — обёртка для браузера: `analyze` (оценка и разметка для подсветки)
  и `measureLegacy` (ответ в формате старого API) возвращают JSON.
- `crates/pr-wasm-clarity` — отдельный модуль проверок ясного языка для браузера: загружается
  вместе со словарём, только когда проверку включают.
- `apps/web` — веб-приложение (Vite, Svelte 5, TypeScript): оценка, сравнение с уровнем
  выбранной аудитории, класс по школьной шкале, подсветка сложных
  слов и длинных предложений, переход от находки к месту в тексте, сравнение с исходным
  вариантом при правке, импорт txt, md, html, docx и pdf, офлайн, оценка с помощью
  LLM (`src/lib/llm`, подключается на странице настроек), страница «О проекте».
- `apps/desktop` — настольное приложение (Tauri 2) с тем же интерфейсом: открытие страниц
  по ссылке, ключи API в системном хранилище, любой OpenAI-совместимый LLM-сервис.
- `eval/llm` — бенчмарк оценки LLM на размеченном корпусе.
- `calibration` — корпус с экспертными оценками, признаки текстов, подбор коэффициентов
  и отчёт `REPORT.md` с ошибками формул; описание нового корпуса в `graded` и скрипт
  его сборки.
- `tools` — генераторы эталонов из Python-оригиналов (старый `metric.py` и razdel).

## Проверка

```bash
cargo test --workspace
```

Для сборки `crates/pr-py` нужен Python 3.9 или новее: pyo3 ищет его при компиляции.

На GitHub то же самое выполняет `.github/workflows/ci.yml`: Rust на Linux, macOS и Windows,
сборка сайта (артефакт `site`), Python-пакет с MCP-сервером и настольное приложение для Linux
(артефакт `desktop-linux` с `.deb` и `.AppImage`). Golden-тесты по корпусу там пропускаются:
текстов корпуса в репозитории нет.

Golden-тесты сравнивают Rust с Python-оригиналами без допуска: старый алгоритм —
с `metric.py`, деление на предложения — с razdel 0.5.0. Эталоны лежат в
`crates/pr-core/tests/golden`.

Тексты корпуса защищены авторским правом и в репозиторий не входят: в эталонах есть
только путь, SHA-256 и ожидаемый результат. Тесты ищут тексты в соседнем репозитории
`../plainrussian/api/textmetric/textsbygrade` или в каталоге из переменной
`PLAINRUSSIAN_LEGACY_CORPUS`. Если корпус не найден, такие тесты пропускаются с сообщением.

Пересоздать эталоны (нужен соседний репозиторий `plainrussian`, для razdel — venv
с `pip install razdel==0.5.0`):

```bash
python3 -I tools/legacy-golden/generate.py
```

```bash
path/to/venv/bin/python -I tools/razdel-golden/generate.py
```

### Подпись приложений

Без настройки macOS-приложение получает ad-hoc подпись (`signingIdentity: "-"` в
`tauri.conf.json`): на Apple Silicon приложение из интернета без подписи macOS называет
повреждённым, а с ней пользователь один раз разрешает запуск. Установщик для Windows
не подписан. Полная подпись включается секретами и переменными репозитория (Settings →
Secrets and variables → Actions), менять workflow не нужно; их проверяет и передаёт
сборке `.github/scripts/signing-env.sh`.

macOS: нужен платный Apple Developer Program и сертификат Developer ID Application,
который создаёт владелец аккаунта (Account Holder).

| Секрет | Что это |
|---|---|
| `APPLE_CERTIFICATE` | сертификат с закрытым ключом, `.p12` в base64 (`base64 -i cert.p12`) |
| `APPLE_CERTIFICATE_PASSWORD` | пароль от `.p12` |
| `APPLE_SIGNING_IDENTITY` | имя сертификата: `Developer ID Application: Организация (TEAMID)` |
| `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID` | нотаризация по Apple ID; пароль — пароль приложения с appleid.apple.com |
| `APPLE_API_KEY`, `APPLE_API_ISSUER`, `APPLE_API_PRIVATE_KEY` | или нотаризация по ключу App Store Connect API: ID ключа, Issuer ID и содержимое `.p8` |

Без нотаризации подписанное приложение Gatekeeper всё равно не пропустит без вопроса,
поэтому нужен один из двух наборов для нотаризации.

Windows: ключи новых сертификатов подписи кода хранятся только в аппаратных модулях, поэтому
подписывать в CI можно облачным сервисом — Azure Artifact Signing, Azure Key Vault или
облачным HSM удостоверяющего центра. Подпись задаётся переменными (не секретами):

| Переменная | Что это |
|---|---|
| `WINDOWS_SIGN_COMMAND` | команда подписи, `%1` — путь к файлу (`signCommand` в Tauri), например `artifact-signing-cli -e https://weu.codesigning.azure.net -a Account -c Profile %1` |
| `WINDOWS_SIGN_INSTALL` | необязательно: команда, которая ставит инструмент подписи на сборщик |

Для сервисов Azure добавьте секреты `AZURE_CLIENT_ID`, `AZURE_TENANT_ID` и
`AZURE_CLIENT_SECRET`. Даже подписанный установщик SmartScreen поначалу помечает как
редкий: репутация копится с загрузками, поэтому все выпуски лучше подписывать одним
сертификатом.

Azure Artifact Signing выдаёт публичные сертификаты только организациям из ограниченного
списка стран, России в нём нет; это стоит учитывать при выборе способа подписи.

## Проверки ясного языка

Помимо оценки сервис находит приёмы, которые утяжеляют текст:

- цепочки из трёх и больше существительных в родительном падеже;
- отглагольные существительные («проведение проверки» вместо «проверить»);
- канцеляризмы: «в целях», «в рамках», «осуществлять», «являться», «денежные средства» —
  с заменой для каждого («чтобы», «в», «делать», «это», «деньги»);
- страдательные причастия («утверждённый министерством»);
- аббревиатуры (по словарю; набранные заглавными обычные слова не в счёт).

Части речи и падежи определяет rumorph со словарём из OpenCorpora и Universal Dependencies
(CC BY-SA 4.0); падеж выбирается с учётом соседних слов. Словарь — 16,5 МБ, 7,1 МБ в gzip.
В программах (CLI, Python) он встроен; сайт и настольное приложение раздают его файлом
`assets/ru.dict-<хеш>.gz`, который скачивается при включении проверки и дальше берётся из
кеша браузера (Cache API); с новым словарём меняется хеш, и кеш обновляется. Скрипт
`apps/web/scripts/build-wasm.sh` кладёт его в `apps/web/src/wasm/clarity-pkg` из исходников
крейта; в git файла нет.

Канцеляризмы и их замены — в `crates/pr-core/data/bureaucratese.txt`: слова по начальной
форме, обороты как написаны и обороты по начальным формам; формат описан в начале файла.
Регистр и «ё» при сравнении не важны. Файл встраивается в ядро при сборке.

Проверки различают тексты разной сложности. Находок на 100 слов по корпусу калибровки
(`cargo run -p pr-core --features clarity --example clarity_stats -- <textsbygrade>`;
пример печатает и самые частые канцеляризмы каждого уровня):

| Уровень | Отглагольные | Страдательный | Цепочки | Канцеляризмы | Аббревиатуры |
|---|---:|---:|---:|---:|---:|
| 1–4 класс | 0,36 | 0,64 | 0,01 | 0,03 | 0,00 |
| 5–9 класс | 0,95 | 0,80 | 0,04 | 0,07 | 0,02 |
| 10–12 | 1,45 | 1,43 | 0,03 | 0,39 | 0,20 |
| 15–17 (законы, госдокументы) | 8,72 | 3,26 | 1,17 | 3,82 | 0,58 |

## HTTP API старого формата

`plainrussian-server` отвечает на `/api/1.0/ru/measure/` так же, как старый сервис:
GET с `url=` или `text=`, POST формой `text=...` или JSON. Поля `metrics`, `indexes` и
`status` считаются старым алгоритмом, чтобы прежние интеграции (бот, сайты) получали
прежние числа. Дополнительно в ответе:

- `readability` — оценка текущим алгоритмом;
- `clarity` — проверки ясного языка, если передать `clarity=1`;
- `debug.text` — текст, по которому считали, если передать `debug=1`.

```bash
plainrussian-server --listen 127.0.0.1:9888
```

```bash
curl -d 'text=Мама мыла раму.' http://127.0.0.1:9888/api/1.0/ru/measure/
```

Тексты не сохраняются и не пишутся в журнал. По `url=` сервер загружает только адреса
публичного интернета: внутренние сети, локальные и служебные адреса отклоняются после
разрешения DNS и при каждом перенаправлении. Страница — до 5 МБ, текст — до миллиона
знаков. Ошибки — HTTP 4xx с `{"status": 101, "error": "..."}`, как раньше.

## Python и MCP

Пакет собирается [maturin](https://www.maturin.rs/) в одно колесо (abi3) для Python 3.9+:

```bash
cd crates/pr-py && maturin develop --release
```

```python
import plainrussian
plainrussian.measure(text)["indexes"]["average"]   # оценка, лет обучения, и уровень
plainrussian.measure(text)["school"]                 # класс по школьной шкале и подпись
plainrussian.details(text)["complex_words"]          # сложные слова строками
plainrussian.check_clarity(text)["findings"]        # находки проверок ясного языка
plainrussian.sentenize(text)                         # предложения по правилам razdel
plainrussian.measure_legacy(text)                    # формат старого API
```

MCP-сервер ставится с дополнением `mcp` (`pip install "plainrussian[mcp]"`) и даёт
инструменты `measure_readability`, `find_hard_parts` и `check_plain_language`. Запуск по stdio — `plainrussian-mcp`,
по Streamable HTTP — `plainrussian-mcp --http 127.0.0.1:9000`. Подробнее в
`crates/pr-py/README.md`.

Тесты пакета и сервера:

```bash
cd crates/pr-py && pytest tests
```

## Калибровка

Коэффициенты подбираются на текстах из `calibration/corpus.csv` (колонка `fit`) по их
счётчикам в `calibration/features.jsonl`, поэтому сами тексты для подбора не нужны.
Порядок, если меняется подсчёт:

1. Пересчитать признаки по корпусу:

```bash
cargo run -p pr-core --example corpus_features -- ../plainrussian/api/textmetric/textsbygrade > calibration/features.jsonl
```

2. Подобрать коэффициенты под новой версией (нужен numpy):

```bash
python3 calibration/fit.py --version 2026.2
```

3. Перенести коэффициенты и `average_error` из `calibration/2026.2.json` в `CALIBRATION`
   в `crates/pr-core/src/readability.rs`. Тест `calibration_matches_json` проверяет,
   что они совпадают с файлом.

### Школьная шкала

Кроме главной оценки, каждый результат содержит `school` — класс по школьной шкале.
Это те же пять формул с другими коэффициентами (`SCHOOL_CALIBRATION`,
`calibration/school-2026.1.json`, отчёт `calibration/school-2026.1.md`). Они подобраны на
текстах проверочных работ ФИПИ для 2–11 классов из нового корпуса, каждый класс в подборе
весит одинаково. Главная калибровка на этих текстах завышает учебные и научно-популярные
тексты 7–9 классов в среднем на 6 лет, а подобрать одну шкалу и для школьных текстов, и для
законов не вышло: законы на ней опускаются до 13–15 лет вместо 17.

Ограничения школьной шкалы:

- в проверке по источникам она ошибается в среднем на 1,1 класса, но для 10–11 классов
  текстов мало, и там она занижает оценку примерно на 2–3 класса;
- художественные тексты она занижает, тексты сложнее школьных не различает;
- шкала показывается от 1 до 11 класса, выше — подпись «сложнее текстов для 11-го класса».

Подобрать её заново (тексты корпуса нужны только для шага 3 ниже):

```bash
python3 calibration/fit.py --version school-2026.2 --graded --balance
```

### Новый корпус

Старый корпус мал и состоит из художественных и официальных текстов
(`calibration/REPORT.md`). Новый собирается из текстов, у которых уровень известен из
источника: школьные учебники, экзаменационные тексты, вузовские учебники, законы. Сами
тексты лежат вне репозитория, в репозитории — только описание:

- `calibration/graded/sources.csv` — источники и их уровни, заполняется вручную;
- `calibration/graded/fragments.csv` — фрагменты и их sha256, строит скрипт.

Порядок:

1. Положить очищенный текст источника в `<корпус>/sources/<source_id>.txt` и добавить
   строку в `sources.csv`. Колонки и требования к тексту описаны в начале
   `calibration/build_corpus.py`.
2. Нарезать фрагменты и обновить `fragments.csv`:

```bash
python3 calibration/build_corpus.py <корпус>
```

   Скрипт пишет фрагменты в `<корпус>/fragments` и показывает, сколько собрано на каждый
   уровень. Он ничего не записывает, если в описании ошибка или один и тот же текст
   попал в два источника.
3. Посчитать признаки фрагментов:

```bash
cargo run -p pr-core --example corpus_features -- <корпус>/fragments > calibration/graded/features.jsonl
```

4. Подобрать коэффициенты по фрагментам с `split=fit`:

```bash
python3 calibration/fit.py --version school-2026.2 --graded --balance
```

   Проверка идёт с исключением по источникам: формула подбирается без всех фрагментов
   источника и проверяется на них. Отчёт `calibration/<версия>.md` показывает ошибку и
   смещение оценки по уровням, типам источников и жанрам, ошибку на фрагментах с
   `split=test` и ошибку действующей калибровки на тех же фрагментах.
5. Перенести коэффициенты в `SCHOOL_CALIBRATION` в `crates/pr-core/src/readability.rs`.
   Тест `school_calibration_matches_json` проверяет, что они совпадают с файлом.

Сейчас в корпусе 164 источника: в подборе — контрольные работы по русскому языку
для 2–11 классов, банк естественнонаучной грамотности для 7–9 классов и сборники заданий
по истории, биологии, физике и химии для 5–9 классов из открытых банков ФИПИ; отложены
демоверсии ОГЭ и ЕГЭ и проза из федеральных программ по литературе. Метка у прозы из
программ — класс, в котором её проходят, и с признаками текста она почти не связана.

Тесты скриптов (нужен numpy):

```bash
python3 -m unittest discover -s calibration
```

## Веб-приложение

Нужны Node.js и `wasm-bindgen-cli` той же версии, что крейт `wasm-bindgen` в
`crates/pr-wasm/Cargo.toml`:

```bash
cargo install wasm-bindgen-cli --version 0.2.130 --locked
```

```bash
cd apps/web && npm install
```

```bash
npm run dev
```

`npm run build` собирает ядро, проверяет типы и кладёт статический сайт в
`apps/web/dist`. Его можно разместить на любом статическом хостинге в любом каталоге.

Устройство:
- ядро работает в Web Worker, текст не покидает браузер;
- разборщики docx (mammoth) и pdf (pdf.js) загружаются только при открытии такого файла;
- service worker кеширует всё приложение, после первой загрузки оно работает без сети;
- в сборке действует Content Security Policy: свои скрипты и счётчик Яндекс Метрики,
  внешние запросы — только к Метрике и к провайдерам LLM, если подключить оценку;
- счётчик Метрики (без Вебвизора) есть только в сборке сайта, в настольном приложении
  и на dev-сервере его нет.

## Установка настольного приложения

Установщики лежат в разделе Releases на GitHub. Пока приложение не подписано
сертификатами Apple и Microsoft, при первом запуске система предупредит о неизвестном
разработчике.

**macOS.** Скачайте `.dmg` для своего процессора: `aarch64` — Apple Silicon (M1 и новее),
`x64` — Intel. Перетащите PlainRussian в «Программы» и запустите. Если macOS сообщит, что
не может проверить разработчика, откройте «Системные настройки» → «Конфиденциальность и
безопасность», внизу нажмите «Всё равно открыть» и подтвердите. Это нужно один раз.

**Windows.** Скачайте `.msi` или `-setup.exe`. Если появится «Система Windows защитила ваш
компьютер», нажмите «Подробнее» → «Выполнить в любом случае». В Windows 11 с включённым
интеллектуальным управлением приложениями (Smart App Control) неподписанное приложение
может не запуститься совсем: тогда пользуйтесь сайтом.

**Linux.** `.deb` ставится командой `sudo apt install ./PlainRussian_*.deb`; `.AppImage`
достаточно сделать исполняемым (`chmod +x`) и запустить.

## Настольное приложение

Оболочка Tauri 2 над тем же веб-интерфейсом. Оценку считает то же ядро на WebAssembly,
поэтому результаты совпадают с сайтом. Rust-часть (`apps/desktop/src-tauri`) добавляет то,
чего у страницы в браузере нет:

- **открыть по ссылке**: страница загружается без ограничений CORS, кодировка
  определяется по заголовку, `<meta>` или содержимому (старые сайты в windows-1251),
  основной текст выделяет Readability, как в режиме чтения Firefox;
- **ключи API в системном хранилище**: Keychain в macOS, Credential Manager в Windows,
  Secret Service в Linux, а не localStorage;
- **любой OpenAI-совместимый LLM-сервис**: запросы делает Rust, поэтому CORS и CSP не мешают;
  Ollama работает без настройки `OLLAMA_ORIGINS`;
- **GigaChat**: Rust обменивает ключ авторизации на токен доступа и обновляет его сам;
- **внешние ссылки открываются в браузере**, а окно приложения остаётся на своей странице.

Нужны rustup, Node.js, `wasm-bindgen-cli` (см. «Веб-приложение») и системные зависимости
Tauri для вашей ОС: https://tauri.app/start/prerequisites/

```bash
cd apps/desktop && npm install
```

```bash
npm run dev
```

`npm run build` собирает установщики для текущей ОС: `.app` и `.dmg` в macOS, `.msi` и
`.exe` в Windows, `.deb`, `.rpm` и `.AppImage` в Linux. Как подписать их при выпуске —
в разделе «Подпись приложений».

Веб-часть для приложения собирается в режиме `desktop` (`npm run build:desktop` в `apps/web`):
без service worker и без meta-CSP — политику задаёт `tauri.conf.json`, и она строже
сайтовой: напрямую из окна можно обращаться только к API Anthropic.

## Оценка с помощью LLM

Языковая модель оценивает текст целиком по той же шкале лет обучения, перечисляет
главные препятствия для понимания с цитатами и советует, как упростить. Ключ API
принадлежит пользователю; запрос идёт из браузера напрямую провайдеру, без нашего сервера.

| Провайдер | Как подключается | Текст уходит |
|---|---|---|
| Anthropic (Claude) | `@anthropic-ai/sdk`, структурированный вывод по схеме | в Anthropic |
| OpenAI, OpenRouter | OpenAI-совместимый API, `response_format: json_schema` | провайдеру |
| GigaChat (Сбер), только в приложении | OAuth-токен по ключу авторизации, `response_format: json_schema` | в Сбер |
| Ollama, LM Studio | OpenAI-совместимый API на `localhost` | никуда |

- Для моделей Claude, у которых он есть, включён `fallbacks: "default"`: если модель
  откажется оценивать текст по соображениям безопасности, API само повторит запрос на
  рекомендованной модели.
- На сайте CSP разрешает соединения только с адресами из таблицы и с `localhost`.
  Любой другой OpenAI-совместимый сервис доступен в настольном приложении. Надпись «текст
  останется на этом компьютере» появляется, только если адрес сервера локальный.
- GigaChat работает только в настольном приложении: у API нет CORS. Нужны ключ
  авторизации из личного кабинета, тип доступа (физическое лицо или организация) и
  сертификат Минцифры «Russian Trusted Root CA» в системном хранилище:
  https://developers.sber.ru/docs/ru/gigachat/certificates. Без сертификата приложение
  сообщит об ошибке со ссылкой на эту инструкцию. Токен живёт 30 минут и хранится только
  в памяти.
- Ключ хранится в браузере, только если отмечено «Запомнить ключ».
- Чтобы опубликованный сайт мог обращаться к Ollama, добавьте его адрес в переменную
  `OLLAMA_ORIGINS`; для `localhost` это не нужно.
- LM Studio по умолчанию не отвечает браузеру заголовками CORS, даже на `localhost`:
  включите Enable CORS в настройках сервера (вкладка Developer) или запустите его
  командой `lms server start --cors`. Настольному приложению это не нужно.
- Цитаты модели сверяются с текстом: если модель пересказала вместо цитаты, это видно.

### Переписывание для аудитории

Та же модель переписывает текст или выделенный в поле фрагмент для аудитории из списка
«Для кого текст» (`src/lib/llm/rewrite.ts`, `src/components/RewritePanel.svelte`).

- В запросе — описание читателя, цель по шкале лет обучения, текущая оценка формулами
  (для всего текста), самые длинные предложения и находки проверок ясного языка с заменами
  из словаря канцелярита. Модели проще исправить то, на что ей указали.
- Ответ — обычный текст в тегах `<text>…</text>`, без JSON-схемы: длинный текст внутри
  JSON слабые локальные модели экранируют с ошибками, а `json_schema` есть не везде.
  Запрос к Claude потоковый (`max_tokens: 64000`), ответ собирается целиком.
- Черновик показывается рядом с полем. Числа исходного текста сверяются с черновиком:
  пропавшие (сроки, суммы, номера) перечисляются, чтобы их проверить.
- Текст в поле меняется только по кнопке. Прежний вариант становится исходным для «Было и
  стало», так что изменение оценки видно сразу, а кнопка «Вернуть как было» отменяет замену.
- Переписанный фрагмент остаётся выделенным: его можно переписать ещё раз.
- За один запрос — до 30 000 знаков; длинный текст переписывается по частям.

Бенчмарк прогоняет тот же промпт по 55 текстам калибровки и сравнивает ошибку модели
с ошибкой формул. Облачный провайдер тратит деньги, поэтому без `--yes` скрипт только
показывает объём:

```bash
ANTHROPIC_API_KEY=... node eval/llm/benchmark.ts --provider anthropic --model claude-opus-5-5 --yes
```

```bash
node eval/llm/benchmark.ts --provider ollama --model <модель>
```

Результаты пишутся в `eval/llm/results/` и в git не попадают: в них цитаты из текстов
корпуса.
